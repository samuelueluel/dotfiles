# Stata Refactor

Output-preserving restructuring of Stata do-files. The invariant: **every final output is identical before and after** — saved datasets, parameter estimates, graphs, and tables. This is the safety-first counterpart to `stata-modernize` (which improves code and *accepts* behavior risk). Here, any behavior change is a bug.

This is statistical programming, not software engineering. The bias is conservative: a refactor that yields no improvement is free; a refactor that silently changes a result is expensive. When in doubt, leave it.

## The invariant — precisely

- **Datasets:** content-identical. `datasignature` equal **and** schema equal (type, format, variable label, value-label *contents*, `sortedby`, N, k). Variable (column) order is normalized away before signing — the harness alpha-sorts columns on a throwaway copy — so reordering variable *construction* is output-neutral and will not trip the dataset check; a change to any *value*, type, label, or **observation** order still fails. Raw `.dta` files embed a save timestamp, so file-byte equality is not the target; content+schema equality is.
- **Estimates:** bit-identical. `e(b)` and `e(V)` written in `%21x` (hexadecimal float) match exactly, **and every `e()` scalar is captured in `%21x`** (not just at display precision), plus `e(cmdline)`. A 6th-decimal SE difference fails.
- **Graphs:** content-equivalent. Same plotted-data subset **and** same graph command string. Exported `.gph`/`.png`/`.pdf` carry timestamps, so file bytes are not compared.
- **Tables:** text-normalized. Whatever your code writes as a final table — `esttab`/`estout` output **or a hand-written `.tex`/`.csv` built with `file write`** — is snapshotted with `snap_table` and compared line-by-line at the rounded precision that lands in the paper. Pure-date lines are stripped automatically. For other run-to-run boilerplate the date stripper does not catch — an embedded timestamp, a tempfile path, a "Generated by …" stamp — pass `snap_table … ignore("<regex>")` to drop those lines (one regex; combine patterns with `|`). A table compare that FAILs **only** on such a line, with every number unchanged, is a false alarm: add the line to `ignore()` (or remove the stamp from the table-writing code) — it is **not** a result change. Any change in a displayed number is real and is a result failure.

## THE WALL — never touch the specification

The following are **the researcher's specification, not refactorable structure.** The harness does **not** license crossing this wall. If a refactor seems to require it, **stop and ask** — do not assume.

- The **estimation command** (`regress`, `reghdfe`, `ivregress`, `xtreg`, `logit`, `csdid`, `did_multiplegt`, …). No swapping, no "upgrading."
- **Estimation options** — vce/cluster/robust, `absorb()`, fixed-effects structure, weights, constraints, `if`/`in` on the estimation itself.
- The **estimation sample** — the `keep`/`drop`/`if`/`in` that defines who is in the regression.
- **Analysis-variable construction** — every `gen`/`replace`/`egen` that builds a regressor or outcome. Preserve construction, not just names.
- **`set seed`** value and its position relative to any RNG-using command.
- **`version`** directive and **`merge`** direction/order.

The harness enforces part of this automatically: `snap_estimate` records `e(cmdline)`, so any change to the estimation command or options shows up as a snapshot diff and **fails** `compare.do`. This is a backstop, not a license — do not rely on it to catch what you should never attempt.

## Workflow (always)

1. **Inventory outputs** of the pipeline: every saved dataset, every final estimate, every graph, every table.
2. **Snapshot the ORIGINAL** — the golden master — using `scripts/snapshot.do` (run the pipeline, then capture each output; see the script header for the wrapper pattern).
3. **Classify** each planned refactor **green / yellow / red** per `references/refactor-catalog.md`.
4. **Apply in small batches.** After each batch, re-snapshot the refactored pipeline.
5. **Diff** with `scripts/compare.do <orig_dir> <refactored_dir>`. On any mismatch, **bisect** to the offending batch and **revert it**.
6. **Sign off** only when `compare.do` reports PASS for every output.

## Risk tiers (summary)

- **Green** — provably output-neutral (comment reformatting/relocation — but **preserve** substantive notes: warnings, methodological rationale, citation anchors, non-obvious derivations, TODO/FIXME markers; only remove redundant restatements, dead-code blocks, obsolete comments, and decorative separators — see `references/refactor-catalog.md`; `///` formatting; dead-code removal; path modernization to an identical resolved path; purely internal `tempvar`/local renames). Snapshot as a cheap check.
- **Yellow** — likely neutral but must be harness-verified (reordering independent steps, `foreach` consolidation, `preserve/restore`→`frame`).
- **Red** — structurally changes state or order (reordering `merge`/`append`, changing merge direction, `sort`↔`gsort`, `collapse`→`egen`, extract-to-`program`). Harness mandatory; often not worth the risk.

Full patterns + examples: `references/refactor-catalog.md`.

## Stata traps that make "safe" refactors silently break outputs

`sort`/`sortseed` tie-breaking · `merge`/`append`/`duplicates` sort effects · float associativity in aggregation · `preserve/restore` vs `frame` state · extract-to-`program` local/tempvar scoping · `version` directive · `capture`/`set varabbrev`/`set type` state · `set seed` path · missing-value predicates (`mi()` vs `==.`). Full catalog + the discipline for each: `references/nondeterminism.md`.

## The harness

- `scripts/snapshot.do` — defines `snap_open`, `snap_dataset`, `snap_estimate`, `snap_graph`, `snap_table`, `snap_auto`, `snap_close`. Datasets via `datasignature`+schema; estimates via `%21x` `e(b)`/`e(V)` + `e(cmdline)`; graphs via plotted-data + command string; tables via timestamp-stripped text (`snap_table` also takes `ignore("<regex>")` to drop other volatile boilerplate — embedded timestamps, tempfile paths, "Generated by …" stamps — in hand-written `.tex`/`.csv` tables). Requires Stata 16+ (frames).
- `scripts/compare.do` — diffs two snapshot dirs file-by-file, reports PASS/FAIL per output, flags missing/extra outputs, sets global `COMPARE_OK`, exits nonzero on any mismatch.

Typical wrapper: `do snapshot.do`; `snap_open, dir("snap_orig")`; run the pipeline; call the `snap_*` programs at each output; `snap_close`. Repeat for the refactored pipeline into `snap_new`. Then `do compare.do snap_orig snap_new`.

## Running in a read-only / containerized environment

The workflow above assumes the pipeline can write its outputs to the project's
normal locations. In a containerized setup (e.g., a Podman container with
per-subvolume bind mounts), the skill files, the project's `Data/` and `Temp/`
(or `Results/`) directories are frequently mounted **read-only**, while the
working do-file directory and `/tmp` are writable. The pipeline then aborts
mid-run on its first output write (`r(602)` "file … could not be opened"), so
"run the pipeline" against the real paths is not directly possible.

The accommodation is mechanical and **content-neutral** — it changes no result,
only where intermediate files land. No change to the harness scripts is
required (`snapshot.do`/`compare.do` already write to `$SNAP_DIR` and Stata
tempfiles, both pointable at `/tmp`).

**Key fact: the harness compares snapshot *text*, not datasets.**
`snap_dataset`/`snap_estimate`/`snap_table` write kilobytes of
checksum/schema/%21x/table text. So you do **not** need two copies of the
dataset, and you do not need the project's output directories to be writable.
Peak storage is one dataset in Stata RAM plus two small text snapshot dirs.

**Scratch-root pattern (verified):**
1. Make a writable **scratch root** (e.g. `/tmp/<job>/scratch/`) mirroring only
   the subdirectories the do-file reads/writes:
   - `Data/` → **symlink** to the real read-only `Data/` (read-through; no copy),
   - `Temp/` (and any other output dir) → a real writable directory.
2. Make a **pathed copy** of the do-file in `/tmp` with exactly one line
   changed: `global path "<real project>"` → `global path "<scratch root>"`.
   Do this for **both** the baseline and the refactored run. The substitution
   is identical across the two runs, so it cancels in the comparison; and the
   harness is path-neutral — `_snap_capture_ds` strips the `"Contains data from
   <path>"` header before signing, so the redirected path does not trip the
   dataset compare.
3. Snapshot **in memory** at each save point — `snap_dataset, name(...)`
   against the frame the pipeline leaves in memory — rather than
   `snap_dataset using("...")`. Two reasons: (a) the path is redirected to
   scratch anyway; (b) `syntax [using/]` mis-parses a comma in the filename
   (e.g. `Motor_City_Mapping,_Winter…`), so `using()` errors with `r(198)`.
   For binary exports (`.dbf`), re-import the saved file and snapshot in memory.
4. For any timestamp-free text export (e.g. a `.csv`), add a `sha256` as a cheap
   extra guard: the dataset snapshot **normalizes column order** (it alpha-sorts
   columns on a throwaway copy before `datasignature` *and* `describe`), so a
   column-order change is not caught by the dataset snapshot alone. A csv sha256
   catches it. (True in any environment, not only containers.)

**Execution vehicle.** Running the pipeline plus harness is simplest via
**batch Stata** (`stata-mp -b do wrapper.do`) rather than an interactive MCP
session: deterministic, full untruncated log, and both runs in the same engine.
Run baseline and refactored the same way so the comparison is apples-to-apples.

**Skill files are read-only in-container.** `~/.agents/skills/` is mounted
read-only, so this skill cannot be edited from inside the container — skill
authoring is a host-side task. Edit `SKILL.md` on the host and reinstall.
